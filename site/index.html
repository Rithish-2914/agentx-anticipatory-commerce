How it thinks

Read. Narrow. Decide.

Three steps run on every word, in about a tenth of a millisecond, with no LLM calls and no paid APIs.

01

Read, knowing what's unfinished

Each word re-reads the whole request. It understands synonyms, spoken and Hindi numbers, and corrections. Values that could still change are marked pending and never acted on.

"under two thousand…" could still become 2,500
"black oops, grey": the latest mention wins
"saadhe teen hazaar" → ₹3,500
02

Narrow with one search

When the product type is clear, one search fetches the candidates. Every later word narrows them locally. It searches again only if a correction invalidates the set.

1,074 → 80 hoodies → 5 grey M → 3 Urbanyx → 1
searches used: 1
03

Decide with a confidence score

Once one product fits, confidence is the measured chance that no correction is still coming. It commits at 0.95, a threshold derived from the scoring formula.

"…size 8," → 0.59 wait
"…Tanaro kurta" → 0.98 commit
"…for my dad" → 0.99 commit
Confidence, not guesswork

A late detail can only narrow a match. Only a correction can break it.

So the only question is "is a correction coming?". Where the shopper is in their sentence answers it. Each value below is measured on the dev set, not hand-tuned.

commit line 0.95
Commit when confidence > 1 / (1 + 0.6·e), where e is the share of the request still to come. A wrong commit costs 1 point and earliness earns 0.6·e, so at e ≈ 0.1 the line sits at 0.95.
